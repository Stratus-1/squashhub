# Total PWA Cancellation Plan

## Goal
Remove all PWA (Progressive Web App) functionality from SquashHub, including service workers, install prompts, update prompts, dynamic manifests, and related dependencies. Users who already installed the app will have their service worker cleanly unregistered via a kill-switch.

## Changes

### 1. Build Tool: Remove `vite-plugin-pwa`
- **File:** `vite.config.ts`
- Remove `VitePWA(...)` plugin configuration entirely.
- Remove `import { VitePWA } from "vite-plugin-pwa";`.

### 2. Dependencies: Remove PWA packages
- **File:** `package.json`
- Remove `"vite-plugin-pwa": "0.19.8"` from dependencies.
- Remove `"workbox-core"`, `"workbox-precaching"`, `"workbox-routing"` from dependencies.

### 3. Service Worker: Delete source file
- **File:** `src/sw.ts`
- Delete entirely. With no `VitePWA` plugin, this file is no longer compiled or injected.

### 4. App Entry: Remove all PWA component references
- **File:** `src/App.tsx`
- Remove imports for:
  - `DynamicPwaManifest`
  - `PwaUpdatePrompt`
  - `InstallAppPrompt`
- Remove `<DynamicPwaManifest />` JSX node.
- Remove `<PwaUpdatePrompt />` JSX node.
- Remove the existing commented-out `{/* <InstallAppPrompt /> disabled - iOS install issues */}` line.

### 5. HTML Head: Strip PWA-specific tags
- **File:** `index.html`
- Remove the `<link rel="manifest" href="/manifest.webmanifest" />` tag.
- Remove iOS PWA meta tags:
  - `apple-mobile-web-app-capable`
  - `apple-mobile-web-app-status-bar-style`
  - `apple-mobile-web-app-title`
  - `apple-touch-icon` link
- Remove Android PWA meta tags:
  - `mobile-web-app-capable`
  - `msapplication-TileColor`
  - `msapplication-TileImage`
- Keep standard favicon, theme-color, SEO, and Open Graph tags.

### 6. Component Cleanup: Delete PWA-only React components
- **Files to delete:**
  - `src/components/DynamicPwaManifest.tsx`
  - `src/components/PwaUpdatePrompt.tsx`
  - `src/components/InstallAppPrompt.tsx`

### 7. Main Entry: Simplify service-worker cleanup
- **File:** `src/main.tsx`
- Remove or simplify the `serviceWorker.getRegistrations().then(...)` block used for preview-environment unregistration. It is now redundant because no service worker will ever register.
- Can optionally keep a one-time `unregister()` call as a safety net, but it is not required.

### 8. Kill-Switch for Existing Installs (CRITICAL)
- **File to create:** `public/sw.js`
- Deploy a static kill-switch service worker at the same path the old `VitePWA` served (`/sw.js`).
- This ensures any device that already registered the PWA will receive the new worker on next visit, which:
  1. Claims all clients.
  2. Deletes all caches.
  3. Unregisters itself.
- Without this step, existing installed PWAs would keep serving stale cached content forever.

### 9. Optional: Remove `manifest.webmanifest` from build output
- The manifest was auto-generated by `VitePWA`. After removal, no new `manifest.webmanifest` will be emitted in the build. No file deletion in the repo is needed unless a static copy exists in `public/` (there is none).

## Technical Details
- The `workbox-*` packages are no longer needed because there is no service worker precaching or routing.
- Push notifications rely on the service worker. Removing the SW means web push will stop working in browsers. (Native/Capacitor push via `NativePushListener` is unaffected because it uses the native layer, not the web SW.)
- The `OfflineBanner` component can remain — it detects `navigator.onLine` and is independent of the service worker.

## Verification Steps After Implementation
1. `vite.config.ts` no longer imports `vite-plugin-pwa`.
2. `src/App.tsx` does not import or render any PWA components.
3. `index.html` has no `manifest.webmanifest` link and no `apple-mobile-web-app-*` tags.
4. `public/sw.js` exists with the kill-switch code.
5. Build completes without PWA-related warnings.
