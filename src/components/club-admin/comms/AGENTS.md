# Comms / AGM rules
- AGM nominations precede the secret ballot on the same draft: hashed personal links, eligible-only name search, self-nominations ("make yourself available") auto-accepted only when `allow_self_actions` is on; voting for oneself is the separate `allow_self_vote` option (off = own name hidden and rejected server-side); others need acceptance; at close accepted nominees become candidates and positions lock; why: ballots list only consenting eligible nominees.
- AGM proxies are appointed on the invite link among invitees only, need the holder's acceptance, carry in-person meeting votes only (never online ballot weight), and accepted proxies are disclosed by name; why: the secret ballot stays one vote per member.
- AGM nomination link reissues keep earlier hashes in service-only `agm_nominator_old_tokens` and `_agm_nominator` accepts them; why: a reminder must never break a member's original emailed link.
- Member Communications access (templates, campaigns, delivery log, sending) is decided only by `can_manage_club_comms`: club admins, the `communications` permission, and current office bearers (club officer posts incl. treasurer, open `club_offices` rows); the app reads it via `my_can_manage_club_comms`; why: RLS, sender and the visible tile must agree. AGM ballot administration stays on its own admin checks.
- The "outstanding balance" campaign audience uses `supabase/functions/_shared/comms-outstanding.ts` (member statement net on debtors + member_credits, > R0, active membership incl. arrears suspensions), previewed in the wizard and re-evaluated at send time; why: reminders must reach only members who owe, from the same balance admins see.
- Standard templates every club gets are seeded by `seed_club_welcome_template` / `seed_club_balance_template` / `seed_club_settle_account_template` from the club-insert trigger (idempotent, never overwrite edits); why: new clubs start with the same ready-made messages.
- `{{outstanding_amount}}` is read from the member ledger by the sender at send time and recipients owing ≤ R0 are skipped; admin-unticked owing members are stored as `audience_filter.exclude_member_ids` and enforced server-side; why: a reminder must never quote a stale or zero balance or reach someone the admin removed.
