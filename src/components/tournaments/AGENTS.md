# Tournament UI rules

- Diamond fixtures use `tournamentMatchDays` in `schedule-order.ts` for date headings and time/court order, never generated rounds; why: division weeks span different nights. Display only; saved fixtures unchanged.
- Knockout stages after the first play-off use fixed feeder paths (stage_winners by bracket_position); never reseed from standings — keeps brackets deterministic and auditable.
- Draw/round generation never dispatches player messages: `notifyRoundDraw` only sends when called with `skipPrompt: true` from an explicit organiser send (Send draw to players / future Manage Tournament → Notifications); why: test and regenerated draws must never reach players.
- Swiss standings (page) and Swiss next-round pairing share one ranking, `swissTable` in `src/lib/tournaments/swiss-standings.ts` (match wins; bye = win with no Buchholz credit; Buchholz → Sonneborn-Berger default, configurable `Stage.tieBreaks`; original seed last). Swiss is detected per structured stage, never from legacy `scoring_mode`; why: the table must never show an order the pairing does not use.
- Swiss rounds are created one at a time via `swissRoundGate` (`src/lib/tournaments/swiss-round-gate.ts`): draw makes Round 1 only, Round N+1 only on admin confirm after every real Round N fixture is final (byes/voids final), never skip or exceed `swissRounds`; enforced server-side by DB trigger `guard_swiss_round_progression`; why: pairings must use confirmed results and buttons alone are not security.
- Tournament games split into Upcoming vs Results only via `src/lib/tournaments/fixture-split.ts` (byes/cancelled/walkovers → Results), used by every ClubChampsView layout incl. the public QR view; why: one game must never appear in both lists or differ between app and QR.
- Fixed-position Swiss full draws live only in `swiss_positional_pilot_draws` (pure engine `src/lib/tournaments/swiss-positional-draw.ts`, generated once, fixtures frozen by trigger, results via `swiss_pilot_record_result`), gated by `tournament_swiss_positional_draw`; why: the pilot must never write to live club_champs_matches, rankings or bookings until sign-off.
- Owner-approved exact pairing charts in the Uitsig Club Champs are display-only templates in `src/lib/tournaments/swiss-uitsig-*-chart.ts`, gated to their current club/tournament/category/size/rounds, never written by fixture generation, and they skip strict slot-completeness validation; Ladies A's approved positions override RR display settings and bye substitutions, while saved games stay factual in Log/Calendar; why: category renumbering must not disable the approved preview or change live pairings.
- Playoff PAR and game-count overrides live separately on `tournaments.league_playoff_points_per_game` and `league_playoff_match_formats`; absent entries inherit pool rules, and `applyPlayoffSettings` applies them only to playoff marker rows while stage-scoring shares the format parser; why: playoff Best-of/Play-all choices must not change pool rules or the independent PAR target.
- Score live / Score offline (device scoring) is on for every club via ALWAYS_ON_FEATURES in use-club-beta-feature.ts (no club_beta_features row needed); offline sessions persist per match in localStorage with revision/acked sync through champ_device_reserve/sync/complete RPCs, and champ_device_reservations mirror into champ_marker_locks.scoring_mode so viewers see LIVE · offline; why: markers must never lose points on bad connections while Live scoring behaviour stays unchanged.
- Pool play is a hard boundary: the engine rejects any pool fixture pairing two pools or a pool count ≠ n·(n−1)/2 per leg (`src/lib/tournaments/pool-boundaries.ts`), Generate draw blocks unresolved/duplicated/missing pool places, and standings show one table per generated pool (from persisted `pool_number`); why: cross-pool meetings belong only to a configured play-off stage.
- Any round/stage with a fixed date + time window + selected courts is slotted only by `src/lib/tournaments/formal-stage-schedule.ts` (last configured category first, capacity shortfall blocks); every fixture creation path calls it; why: fixed stages must never produce TBD/player-booked games.
- Swiss next-round progression is shown per division in Manage Tournament via `src/lib/tournaments/swiss-progress.ts` (gate + "main plan stage N = Round N" schedule detection) and generated only through `generateNextSwissRound`; why: one generator for every screen, and a saved round schedule is never a generated round.
- Swiss next-step (`swissTransition` in `src/lib/tournaments/swiss-progress.ts`) compares setup's stage plan with the live spec after each complete round; disagreements (round count vs planned play-offs) are surfaced as a conflict with explicit admin choices, never resolved by skipping or adding rounds; why: a setup edit after the draw does not change the live Swiss stage.
- Play-off stages set up later (Swiss→KO, pool→KO, QF/SF/Final) never take typed scoring: they inherit the category's saved structured scoring via `src/lib/tournaments/stage-scoring.ts` (same per-division columns the marker reads), shown read-only, and missing/invalid values block set-up; why: one canonical scoring config, no unvalidated free text or guessed defaults.
