# Step-by-Step Beta planning rules (invites, guide, weekend play-offs)

- Step-by-Step "Pick players" stores `picks[memberId]` as a list of event keys (legacy single string read via `placesOf` in `src/lib/smart-builder/pick-entries.ts`); handover sends one item per (person, event) and DB `step_sync_admin_entrants` folds them into ONE registration with `division_choices` + per-event partner `club_champs_registrations.division_partners` (read via `registration_partner_for` / `partnerIn`, legacy fallback `partner_member_id`); `step_prepare_draw` checks duplicates and pairs per event; why: one person may enter several events with different partners without duplicating the person.
- Weekend play-offs are globally gated: the first play-off stage of every event starts only after ALL qualifying games of the tournament (every category) end plus the configured gap, or the fixed start if later (a fixed start earlier than qualifying is reported as a conflict); play-off fixture headings always lead with the event name via `playoffHeadingText`; why: playoffs were scheduled before other categories' qualifying finished and '#1 vs #4' rows were ambiguous.
- Step-by-Step invite mode sends real invitations via `src/lib/smart-builder/step-invite.ts` + `StepInvitePanel`: audience (all club / clubs / league teams / individuals) resolves through the shared fail-closed `resolveInviteAudience`, rows are planned by `planInviteRows` (declined/cancelled re-open, confirmed entries never touched), and sends go through the Comms engine with per-recipient entry links; why: one audience engine, and a selected send can never widen beyond the picked audience.
- Step-by-Step Beta "Structure guide" step (after Categories) stores advisory answers on `StepAnswers.guide`; recommendations come from pure `src/lib/smart-builder/structure-guide.ts` (scored by goal, opponent preference, time capacity and field size — never a fixed size→format rule) and are applied to format/pool/playoff plans only on "Use recommendation"; a materially different picked field prompts review on Stages & scheduling / Dates without overwriting; why: guidance must never silently decide the competition structure.
- Structure guide capacity is numeric (courts × hours/court/day × days, ÷ match minutes) via `guideCapacity` in `src/lib/smart-builder/structure-guide.ts`; slots are shared across categories by `shareSlots` and recommendations score against that share, legacy `guide.time` is read only when no capacity is entered; management "Review / Finalise Structure & Format" reopens the builder at the Guide step with actual entries; why: capacity must come from maths, never let one category claim the whole tournament, and old answers keep working.
- Weekend (timed) tournaments book knockout play-off games via `src/lib/tournaments/weekend-playoffs.ts`, straight after the previous stage's last game and each round after the previous round, inside `format_plan.days`; the general timed scheduler never places knockout games; `auto-progress-tournaments/engine.js` must be rebuilt (`bun scripts/build-auto-progress.ts`) and redeployed whenever `src/lib/tournaments/` changes; why: a stale server bundle seeded play-offs wrongly and play-offs were dated before the stage they follow ended.
- Step-by-Step Beta pool creation belongs on the lowest configured grouping in Subcategories (`poolPlan`: none / auto with target / decide later); playoff qualification belongs in Playoffs or Club Champs Stages & scheduling (`playoffPoolQualifiers`, with legacy `poolPlan.perPool/runnersUp` read fallback). Real pools are proposed from actual entrants at Generate draw, "Decide later" blocks until accepted, and between-subcategory pool play blocks rather than guessing a mapping; why: pools subdivide a subcategory, never replace it, and qualification depends on the planned playoff field.
