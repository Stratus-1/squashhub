# Tournament domain rules

- Stage lifecycle (waiting/ready/blocked/active/completed/deferred/needs_setup) and automatic progression live in `src/lib/tournaments/progression.ts`; predefined stages start via the same engine calls after a dry run, Define-later stages are set up on the live tournament via `setupDeferredStage` (append-only `set_spec` commit op), tie orders go in `TournamentSpec.positionOrders`, and the DB trigger `guard_structured_stage_round_once` refuses a second copy of a stage round; why: progression must never guess, never disturb earlier stages, and never double-generate.
- Diamond League is a normal-wizard team mode: `team_league_events` links 1:1 by `tournament_id`; `autoSlotPlayers` preserves locks; `buildPoolWeeks` drives preview, saved weeks and stable `dl:` match rows; why: invitations, courts, Upcoming, marking and standings must share one tournament fixture identity. Per-division schedules live on `config.divisionSchedules[pool]` (play days/start date/start time → per-tie `date`/`time`, courts restart per own night; missing = shared weekly dates) , optional `config.firstWeekPairs[pool]` relabels the round robin so week 1 matches the organiser (later weeks derived, invalid plans fall back to default), and `config.playoffs === false` stops semis/finals; why: divisions may play different nights without breaking legacy events.
- Diamond League doubles pairs are re-seeded by DB trigger `diamond_seed_doubles_from_singles` once a tie's singles are all scored (points scored, level -> higher position); why: pairing is automatic and never touches started doubles.
- Tournament round dates come from `src/lib/tournaments/round-plan.ts`: setup asks only for opening rounds the pools need and the play-off rounds the play-off type has; play-off games are dated only by their play-off round (`playoffDeadline`), never a pool round; why: play-offs borrowed Round 1's date.
- Per-stage scheduling (pools vs each play-off round: play-by date or fixed date & courts) is stored as `milestone_play_by.stage_scheduling` and resolved by `stageModeForGame`/`playoffModeFor` in `round-plan.ts`, falling back to `scheduling_mode`; why: `club_champs` is a view with INSTEAD OF triggers, and owners mix play-by pools with booked finals.
- Tournament entry fee "settled" means paid, waived OR `on_account` (`champ_member_fee_settled`); every payment route (Stitch start, invite payment context, account charge, pair payment) checks it first, and a partner's fee charged to account moves the debt to the payer via `step_charge_pair_to_account` (partner's own charge reversed with audit); why: one authoritative settlement status, never a second charge or the wrong member's account.
- Tournament bookable courts resolve in DB `tournament_bookable_court_ids` (stage override courts/venue → explicit venue courts → legacy court_ids → host clubs' normal courts), mirrored in `src/lib/tournaments/bookable-courts.ts`; club events default to the owning club, regional/national need an explicit host club; the booking window and the match-court guard both read it; why: owner is never venue and the UI must never offer a court the backend rejects.
- Fixed-date round-robin/cross-league rounds (incl. Bells) are timed by `scheduleTimedRounds`/`planTimedRounds` in `src/lib/tournaments/formal-stage-schedule.ts`: each round starts together at its bell (slot = match_duration_minutes + buffer) on the plan day's own courts, next round one slot later, all-or-nothing on capacity (waves only when `format_plan.waves`); why: fixed Bells evenings need real times/courts, never TBD overflow.
- Tournament entry fee is charged per event: DB `champ_reg_own_due_cents` = event fee x events the player pays for themselves (no choices = 1 legacy event); a partner's cover is per event (`club_champs_registrations.covered_events` or a pay-for-partner `champ_doubles_pairs` row) and pairs confirm via `champ_member_event_paid`; unpaid fee amounts change only through audited `_champ_fee_adjust`, paid fees never change (extra events add an 'additional events' fee); client mirror in `src/lib/tournaments/entry-fee.ts`; why: multi-event entries must owe one fee per event and paying for a partner covers only the shared doubles event.
- Tournament registration status honours `payment_timing`: with pay-before-entry off, payment never gates entry and is reported only via `fee_status`; why: unpaid entrants must still count and be draw-eligible.
- Tournament entry-fee basis lives on `tournaments.entry_fee_basis` (per_player/per_category; NULL = Needs confirmation, never back-filled) + `entry_fee_mixed_rule`; amounts come only from `src/lib/tournaments/entry-fees.ts` / DB `champ_registration_fee_lines`; every payment route first charges the fee via idempotent `ensure_tournament_entry_fee` (claim submit, claim approve, card settlement) and the payment then settles that one charge (bulk `champ_fee_post_charges` deprecated, no UI); member "already paid" reports are `champ_payment_claims` settled only by admin `champ_payment_claim_review` (excess → member credit topup); why: never guess a fee basis, double-charge, or mark paid without verification.
- Timed tournament scheduling places each round only on configured nights inside the 7 days ending on that round's play-by date (one round per week, shared by every category); a round with no night in its week writes nothing; why: rounds must never be packed into an earlier round's week.
- Swiss positional previews use the same template as the fixture writer (`swissPreviewFinalsTemplate` = `preferredSwissTemplate`, frozen 24-player chart in docs/SWISS_24_PLAYER_TEMPLATE.md); why: a preview that differs from the writer mislabels saved games and invents wrong leftover pairings.
