# Tournament scheduling and structure rules

- Standings championship outcome/awards live on `tournaments.beta_lifecycle.standings_awards` via `src/lib/tournaments/standings-outcome.ts` (absent = existing behaviour; winner source stays the progression config; Wooden Spoon only when complete); why: never assume every tournament crowns an individual.
- Weekend "Assign courts & times" drafts the timetable from Courts & Dates only (`format_plan.days`, `format_plan.scheduling` slot estimates, `format_plan.courtRules`) via `src/lib/tournaments/assumed-schedule.ts`; all-or-nothing, played/booked games never move, rest relaxed only when nothing else fits and reported; missing settings deep-link to `/club-admin?tab=champs&setup=<id>&step=Courts`; why: one source of truth for courts/dates and the scheduler never silently produces an invalid schedule.
- Weekend "Assign courts & times" (`src/lib/tournaments/assumed-schedule.ts`) plans the whole tournament in one run: qualifying games, existing TBD knockout/play-off rows, and planned play-offs without rows yet (`provisional-playoffs.ts`, labels from the configured per-stage pairing) held as idempotent `sbs:<champId>:po:<unit>|<QF|SF|Final|place>|<n>` court reservations that real play-off rows adopt in bracket order via `adoptProvisionalSlots` (called from `schedulePlannedPlayoffGames`); pacing and playoff start live on `format_plan.scheduling`; Standard games use Courts & Dates estimates, Bells games their own slot; why: play-off courts must be reserved before qualifying fills capacity, and capacity shortfalls must warn, never drop games.
- The fixed-date timed planner (`formal-stage-schedule.ts`) resolves play format via `resolveTimedFormat` from plan scoring (category/subcategory override → default) and Standard game length from Stages & scheduling, then the structure page planned/per-pool minutes, then `match_duration_minutes`; `tournament_rules.scoring_mode` is only a legacy fallback when the plan has no scoring, and no format forces a whole round to start together; why: Bells lockstep and stale Bells mode leaked into Standard tournaments.
- Whole-weekend tournaments (Courts & Dates scheduling, no stage timeline) turn the Playoffs answer into real predefined play-off stages (pairing only from the answer, else Define later); Generate/Rebuild then adds provisional TBD fixtures via `src/lib/smart-builder/playoff-placeholders.ts` (stage_key `<stage>#ph`, placeholder_a/b from the stage mapping) which Assign courts & times schedules, and `adoptPlaceholderRows` hands each slot to the real stage game then deletes the placeholder; why: the full structure must be visible and hold court time before qualifiers are known, without duplicates or engine changes.
- Category court/evening preferences live on `beta_lifecycle.scheduling_prefs.categoryCourts` (unit key "Cat" or "Cat::Sub", subcategory replaces category; `weekdays` = day-of-week of planned dates; `rule` preferred/only covers both) and are applied only by `planPrefWaves`; tournaments scheduled through Stages & scheduling ("Scheduled" rounds) get their days from `beta_lifecycle.answers.stages` (via `loadTimedContext` fallback, plus `scheduledRounds` scoping in `scheduleTimedRounds`), and `applySetupSessions` ("Place games on courts") honours the same prefs with a plain-placement fallback; why: one planner for preview and allocation, no per-date config, and both scheduling paths share the preferences.
- Stages & scheduling timeline, collapsed stage summaries and court calendar are read-only views derived by `src/lib/smart-builder/schedule-view.ts` from saved stages (planned reservations, never bookings); why: the presentation must never write or reinterpret the schedule.
- Ongoing draw/round player notices live in the permanent "Player Notifications" section of `StepTournamentManagement` (`PlayerNotificationsSection` + shared `DrawNoticeComposer`, scopes from `src/lib/smart-builder/notification-scopes.ts`); revisiting a completed Generate draw step is read-only unless "Amend draw (controlled)" is chosen; why: one renderer for preview/test/send and no accidental regeneration from a completed step.
- Planned Format stage plans live on Step answers `stagePlans` (pure logic `src/lib/smart-builder/stage-plan.ts`); Stage 1 is mirrored to `format`/`formatOverrides`, status is derived from games, saves create `tournament_plan_versions` rows via `save_tournament_plan_version` and never touch fixtures/bookings; why: one plan authority with backward-compatible readers and explicit, separate apply approval.
- Step-by-Step Beta play-off stages on Stages & scheduling are synced from the structure page's per-category Planned playoffs (`src/lib/smart-builder/structure-playoffs.ts`): rounds all categories play stay shared, others are scoped per category, unticked rounds removed; only dates/times/courts are edited there; why: one place decides which rounds each category plays.
- Timeline play-offs (Stages & scheduling rows with phase=playoff) are appended to a running structured spec on explicit setup saves via `src/lib/smart-builder/attach-timeline-playoffs.ts` (category-scoped, append-only, default start auto), and shown upfront as a display-only planned bracket (`src/lib/tournaments/planned-playoff-bracket.ts`) whose positions become names only when the qualifying stage is complete; why: no placeholder rows that could be booked or scored, and setup play-offs must never silently stay unattached.
- Tournament Structure base formats are Swiss / Round robin / Knockout / Monrad; "pools + knockout" is Round robin (pool count, legacy `pools` kind kept internally) plus a Knockout playoff stage; Monrad maths live in `src/lib/smart-builder/monrad.ts` (planning only, draw generation not wired) and format help in `format-help.ts` (toast on intentional selection, dismissible via localStorage); why: one clean format list and no fixtures from an unsupported generator.
