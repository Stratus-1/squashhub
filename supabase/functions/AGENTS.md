# Edge function rules
- Access devices may carry an optional `club_devices.min_age` (NULL = unrestricted); device-control enforces it server-side on unlock via `_shared/member-age.ts` (DOB, then SA ID), unknown age is a separate denial from underage, and denials log to access_events; why: one reusable age gate, never a club-specific hard-code.
- Outstanding-balance plans (`mandate_arrears_plans`) are separate from fee mandates: they finance only `member_outstanding_breakdown().uncovered`, snapshot `covered_fee_ids`, and may share one combined debit, but each component is settled/tracked separately and the plan part drops off when done; why: no double-financing of membership.
- GCP Player API reaches web data only via secret-gated `mobile_*` RPCs (anon-callable) and the `player-admin-inspection` function for service-role-only admin RPCs; why: the service-role key never leaves the backend and mobile never duplicates web-owned records.
- Mobile EFT top-up proofs go through `player-admin-inspection` only: the bridge issues the random `payment-proofs/<club>/<member>/topup-<uuid>.<ext>` path (signed upload, no upsert), confirm accepts only that exact scoped path, checks the stored object (≤10 MiB), dedupes on club/member/proof_url and inserts the same pending EFT row as web; why: callers never choose storage paths and one proof can create only one pending top-up.
- Unpaid card GoBook Lights top-ups expire after 24h (`_shared/lights-topup-expiry.ts`): the hourly process marks them abandoned and the payment trigger never releases them; EFT requests do not expire; why: a card checkout cannot be resumed and later payments must not fund stale requests.
- Every club device path (main door, `device-control` registry devices incl. legacy court relays, manual court lights, Bluetooth backup config) refuses suspended/resigned members via `member_access_blocked`, with only club admins exempt; why: suspension must cut all IoT access, not just the main door.
- Tournament join activation emails go only through service-role `tournament_join_issue_activation` (eligibility, rate limits, audited player-supplied email that never matches an existing login); why: a public link must not leak emails/tokens or let someone attach their login to another member by email auto-linking.
- IoT connectivity alerts reuse the Shelly Cloud `online` flag via `iot-connectivity-monitor` (cron poll, read-only), with per-device outage state in `club_iot_device_health` (grace period, one offline + one recovery email via club SMTP) and settings in `club_iot_alert_settings` (≤2 member recipients); unknown status never alerts; why: no competing health mechanism, no false/noisy alerts, club-scoped.
- Help Center product actions (`help-center-case-action`): only reply/set_status, same workload/IAP/operator/tenant gates as case-context plus `is_platform_admin` for the IAP email's single auth user; all writes go through service-only `help_center_apply_case_action` (latest-revision/held/active/idempotency checks, append-only body-free `help_center_case_actions`), reply email only to the ticket owner; why: SquashHub roles stay authoritative and existing triggers publish revisions.
- Mobile reads/writes of web-owned RPCs add a defaulted `p_sync_secret` path checked by `mobile_internal_secret_ok` plus the exact club/member match (writes also take the API's verified `p_club_id`), never a parallel function; a supplied invalid secret never falls back to `auth.uid()`, and Player payloads only gain additive keys, because web and Player app must share one logic and web callers stay unchanged.
- Help Center case-context failures log only a fixed `diag_code` with allowlisted value-free detail (`diagnostics.ts`) while public responses stay the identical fail-closed body; why: production refusals must be diagnosable without leaking ticket, identity, tenant or content data.
- Junior birth-date reminders: daily `junior-dob-reminders` sends only to `junior_dob_due()` (service-only) people, claiming `junior_dob_reminders(person, round, channel)` before each send; the link is a hashed single-use 30-day token in `junior_dob_links`, and public `junior_dob_submit` only fills an empty `people_private.date_of_birth` with a value-free audit row; why: no double sends, no login needed, and a link can never overwrite or reveal a saved birth date.
- Visitor fee payable immediately (`clubs.visitor_fee_prepay_required`, Stitch only): a member's visitor-guest booking needs enough account credit (`member_account_gate` incl. other uncharged visitor bookings) or a paid `visitor_fee_prepayments` row; trigger `zzz_enforce_visitor_fee_prepay` enforces it on every booking writer, Stitch purpose `visitor_fee` takes the amount only from the server row and is never swept onto older fees, the fee is still charged at slot time, and cancelling releases the prepayment for the next visitor booking; why: old debt must not swallow the visitor fee and no booking path can skip it.

- Broad platform updates (all/association/plan audiences) skip `tenant_type = association` tenants; only explicit club or admin picks reach them; why: associations and junior bodies have no members or club-admin features.
