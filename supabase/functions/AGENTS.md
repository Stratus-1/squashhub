# Edge function rules
- Access devices may carry an optional `club_devices.min_age` (NULL = unrestricted); device-control enforces it server-side on unlock via `_shared/member-age.ts` (DOB, then SA ID), unknown age is a separate denial from underage, and denials log to access_events; why: one reusable age gate, never a club-specific hard-code.
- Outstanding-balance plans (`mandate_arrears_plans`) are separate from fee mandates: they finance only `member_outstanding_breakdown().uncovered`, snapshot `covered_fee_ids`, and may share one combined debit, but each component is settled/tracked separately and the plan part drops off when done; why: no double-financing of membership.
- GCP Player API reaches web data only via secret-gated `mobile_*` RPCs (anon-callable) and the `player-admin-inspection` function for service-role-only admin RPCs; why: the service-role key never leaves the backend and mobile never duplicates web-owned records.
- Mobile EFT top-up proofs go through `player-admin-inspection` only: the bridge issues the random `payment-proofs/<club>/<member>/topup-<uuid>.<ext>` path (signed upload, no upsert), confirm accepts only that exact scoped path, checks the stored object (≤10 MiB), dedupes on club/member/proof_url and inserts the same pending EFT row as web; why: callers never choose storage paths and one proof can create only one pending top-up.
- Unpaid card GoBook Lights top-ups expire after 24h (`_shared/lights-topup-expiry.ts`): the hourly process marks them abandoned and the payment trigger never releases them; EFT requests do not expire; why: a card checkout cannot be resumed and later payments must not fund stale requests.
- Every club device path (main door, `device-control` registry devices incl. legacy court relays, manual court lights, Bluetooth backup config) refuses suspended/resigned members via `member_access_blocked`, with only club admins exempt; why: suspension must cut all IoT access, not just the main door.
